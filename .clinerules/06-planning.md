# Pläne erstellen

- Jede Aufgabe, die mehr als einen zusammenhängenden Codeschritt braucht, bekommt zuerst einen kurzen schriftlichen Plan, bevor Code geschrieben wird. Kein Implementieren direkt aus dem Kontextfenster ohne Doku davor.
- **Kleiner Plan** (passt in ein bestehendes Arbeitspaket aus `docs/earshot-voice-plan.md`): als Todo-Liste im Commit-/PR-Text, plus Haken in `docs/PROGRESS.md` setzen.
- **Größerer Plan** (neues Feature, ändert Umfang oder Reihenfolge eines bestehenden Arbeitspakets, betrifft mehrere Dateien/Systeme):
  1. Zusammenfassung + vorgeschlagene Schritte dem Nutzer zeigen, BEVOR Code geschrieben wird.
  2. Erst nach Bestätigung: Plan als neue Checkliste in `docs/earshot-voice-plan.md` einfügen (passende Phase, oder neue Phase am Ende, falls nötig) — nicht nur im Chat stehen lassen.
- Bestehenden Plan nie stillschweigend umsortieren oder Punkte löschen. Nur ergänzen, oder ändern mit kurzer Begründung, immer nach Rückfrage.
